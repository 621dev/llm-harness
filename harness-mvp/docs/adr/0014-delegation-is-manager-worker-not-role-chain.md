# ADR 0014 — `hierarchical_delegation`을 매니저-워커로 재작성한다 (역할 체인 폐기)

- 날짜: 2026-08-13
- 상태: 채택
- 관련: ADR 0009(체인 강등), ADR 0011(병합 폐기), ADR 0013(체인 최종본 선택), ADR 0007(agentic_task)

## 배경 — 의도와 구현이 갈라져 있었다

이 패턴의 **원래 의도는 컨텍스트 절약**이었다. `subagent_runner.py`의 docstring이
`gaebalai/claude-code-orchestrator`를 인용하며 그렇게 적어뒀다:

> `delegate()`는 provider 호출 결과(전체 내용)는 `artifacts/chain/step-N-role.md`로만
> 저장하고, 호출부(메인 Orchestrator)에는 요약된 Observation(summary + output_ref)만
> 반환한다 — 이게 gaebalai/claude-code-orchestrator에서 가져온 "컨텍스트 격리"
> 시뮬레이션이다.

**구현이 두 군데서 의도를 벗어났다.**

1. **격리가 토큰이 흐르지 않는 채널에만 걸렸다.** 같은 docstring이 이어서 인정한다 —
   "이 격리는 메인 Orchestrator에게 무엇을 보여주는가의 문제이지 체인 내부 단계 간
   정보 전달을 막는 게 아니라서, `run_chain()`이 다음 단계의 입력을 만들 때는 저장된
   파일에서 **이전 단계의 전체 내용을 다시 읽어 넘긴다**."
2. **보호받던 "메인 Orchestrator"가 LLM이 아니었다.** Python 코드다 — 컨텍스트 창도
   구독 한도도 없다. 요약해서 넘겨도 **아끼는 자원이 존재하지 않았다.** 반면 실제 토큰이
   흐르는 단계→단계 채널은 전문을 실어 보냈다.

참조한 저장소에서 매니저는 **claude**, 즉 실제 컨텍스트 창과 5시간/주간 롤링 한도를 가진
주체다. 거기서는 요약 전달이 진짜 절약이 된다. 우리 구현에서는 아니었다.

## 측정이 말한 것과 말하지 않은 것

실측(시도 78회 집계):

| 조건 | 합격률 | 입력토큰 | 증폭 |
|---|---|---|---|
| direct (기준선) | 0.67 | 74 | 1× |
| chain (3역할) | **0.43** | 5,806 | **78×** |
| departments (5역할) | 0.83 | 23,660 | **320×** |

**ADR 0009는 이 결과로 체인을 강등했고, 그 판단은 맞다.** 다만 잰 것은 *"역할을 쪼개면
품질이 오르나"* 였다(답: 아니오 — 기준선보다도 낮다).

**원래 목적인 컨텍스트 절약은 한 번도 측정되지 않았다.** 그래서 ADR 0009의 근거를 이
재작성에 그대로 적용할 수 없다. 재는 축이 다르다:

- ADR 0009가 잰 축: 합격률
- 이 ADR이 재야 할 축: **완료된 작업당 매니저가 쓴 입력 토큰·구독 호출 수**

## 결정

**역할 체인을 폐기하고 매니저-워커로 재작성한다.** 누적(chain)을 팬아웃(fan-in)으로 바꾼다.

```
1. 분해   매니저(claude) 1회 -> DelegationPlan(문서 제목 + 머리글 + 조각 목록)
          본문이 아직 없으므로 매니저는 본문을 볼 일이 없다. 입력·출력 모두 작다.

2. 실행   조각마다 워커(codex/gemini) 1회. **조각끼리 서로를 보지 않는다.**
          각 워커 입력 = 원본 요청 + 자기 지시. 전문은 artifacts/parts/ 파일로만.
          워커 사이는 병렬, 같은 워커의 조각은 순차(rate limit 겹침 방지).

3. 조립   concat: 매니저 계획의 뼈대에 조각 파일을 끼운다. **LLM 호출 0회.**
          llm:    매니저가 조각을 받아 한 번 다시 쓴다(조각 총량 × 1회).
```

**핵심은 입력 증폭이 조각 수에 선형이라는 것이다.** 체인은 제곱에 가까웠다.

부수 결정 넷:

1. **매니저는 워커가 될 수 없다.** 워커는 `__worker__:` 접두사로 **명시 등록된 것만**
   고른다. "예약 키를 뺀 나머지"로 고르면 후보 목록의 claude가 새어 들어와 매니저가
   자기에게 위임하게 된다 — 조용히 틀리는 것보다 "워커가 없다"고 실패하는 게 낫다.
2. **기본 조립은 `concat`이다.** 이 패턴이 아끼려는 게 매니저 토큰이므로.
3. **조각 수 상한은 코드가 갖는다**(`max_delegation_parts`, 기본 6). 상한을 매니저
   판단에 맡기지 않는다 — 조각 하나가 곧 워커 호출 하나다.
4. **`plan.delegation_chain`을 쓰지 않는다.** 조각은 planner가 정적으로 정할 수 없고
   매니저가 요청을 보고 런타임에 결정한다. 그게 "매니저가 지휘한다"의 실체다.

## `concat` 조립이 ADR 0011의 실패와 다른 이유

ADR 0011은 "상위 두 후보를 이어붙이는" 병합을 없앴다. 이유는 **완결된 문서 두 개**가
붙어서 "절차서 하나를 써줘"에 둘을 내놨기 때문이다(7차 측정, 12개 run 중 9개).

여기는 다르다. 조각은 처음부터 **겹치지 않는 섹션으로 설계된 것**이고 뼈대도 매니저가
미리 정했다 — 이어붙이는 게 맞는 유일한 경우다. 그래서 분해 프롬프트가 "섹션끼리
내용이 겹치면 안 된다"를 명시하고, 그 이유("각 작성자는 다른 섹션을 보지 못한다")까지
알려준다.

**이 구분이 무너지면 ADR 0011의 실패가 재현된다.** 분해가 겹치는 섹션을 만들면 최종
문서에 같은 내용이 두 번 들어가고, `concat`에는 그걸 잡을 주체가 없다.

## e2e 실측 (2026-08-13) — 실제 배치로 확인

`examples/task.delegation.json`, **매니저 claude + 워커 codex**(운영 config 그대로).
구독 4회 = 분해 1 + 조각 3, 조립 0회. 129초, 실패 0건.

mock으로는 볼 수 없던 것 넷이 확인됐다:

1. 실제 claude가 **파싱 가능한 분해 JSON**을 준다(산문/코드펜스로 감싸지 않았다)
2. **매니저가 조각 본문(3,515자)을 한 글자도 안 받았다** — 이 패턴의 존재 이유가 성립
3. **조각이 겹치지 않았다**(세 쌍 전부 겹치는 문장 0개) — `concat`의 유일한 위험이자
   ADR 0011 재현 경로였는데 발생하지 않았다
4. 작업 보고문·섹션 제목 혼입 없음

**단 이것은 "동작한다"이지 "이득이다"가 아니다.** 컨텍스트 절약이 실제로 값을 내는지는
같은 조건 비교(`--conditions direct,fan_out,delegation`)로 따로 재야 한다.

## 결과 / 한계 (숨기지 않는다)

- **매니저가 조각 본문을 검토하지 않는다**(`concat`). 조각 사이의 중복·모순을 잡는
  주체가 없다. `llm` 모드가 그걸 하지만 조각 총량만큼 토큰을 쓴다 — 절약과 정합성의
  교환이고 기본값은 절약이다.
- **아직 매니저가 도구를 쓰지 않는다.** 진짜 에이전트 매니저라면 조각을 골라 읽고 다시
  위임할 수 있어야 하는데, claude에 Bash/MCP를 열어야 해서 ADR 0007의 안전 경계를
  건드린다. 이 단계에서는 하네스가 순서를 돌리고 매니저는 분해·조립만 한다.
- **여전히 opt-in이다.** 키워드 자동 라우팅은 붙이지 않는다 — e2e로 동작은 확인했지만
  **값을 낸다는 측정은 아직 없다.** ADR 0009가 값 없는 경로를 기본값으로 두지 않은 것과
  같은 이유이고, **재작성했다는 사실도 e2e가 성공했다는 사실도 값의 증거는 아니다.**
- **체인 코드(`subagent_runner.py`)는 아직 제거하지 않았다.** `delegation_chain`이
  16개 파일에 걸쳐 있어 한 번에 지우면 변경이 검토 불가능해진다. 별도 정리 작업이다.

## 기각한 대안

- **에이전트 매니저(claude에 도구를 열어 스스로 위임)**: 목표에 가장 가깝지만
  `--allowedTools Read,Write,Edit`으로는 워커를 못 부르고, Bash를 열면 ADR 0007의
  작업공간·도구 경계가 무너진다. MCP 도구로 워커를 노출하는 게 정공법이고, 그건 별개
  작업이다.
- **체인을 유지한 채 단계 간 요약만 넣기**: 요약을 만드는 것도 LLM 호출이라 단계마다
  비용이 붙고, 요약 손실이 다음 단계로 전파된다. 무엇보다 **순차 의존 자체가 값을 낸다는
  증거가 없다**(ADR 0009). 순차를 유지할 이유가 없었다.
- **패턴 이름 변경**: `hierarchical_delegation`이라는 이름은 매니저-워커에 오히려 더
  맞는다. 이름을 바꾸면 스키마·config·opt-in 문자열이 전부 흔들린다.
